# AGENTS.md

Read `README.md` and use the toolchain pinned in `rust-toolchain.toml`. Follow the sibling tafrigh-rs, tahweel-rs and tashkeel-rs conventions: the root package is `quran-detect-cli`, the binary is `quran-detect`, and reusable code lives in `crates/quran-detect`.

Use workspace dependencies and lint settings, Conventional Commits, and concise documentation with detailed explanations in `docs/`. Keep each prose paragraph on one source line. CLI declarations live in `src/cli.rs`; regenerate the CLI reference and man page with `sh scripts/cli-docs.sh` after changing them.

The matcher is a faithful port of the Python reference (`quran-matcher` 0.2). Internally it works in code-point offsets exactly like the reference and converts to UTF-8 byte offsets only at the public boundary. Do not change matching, normalization or rendering behavior without fresh held-out evaluation; any such change must be deliberate, documented, and reflected in `scripts/parity.py` expectations. Character classes, CPython whitespace and HTML entities come from `src/tables.rs`, generated by `scripts/generate-tables.py`; never edit it by hand.

Never modify the files in `crates/quran-detect/data/tanzil/`: Tanzil's terms allow verbatim copies only, and tests pin their hashes. Keep Tanzil's attribution in the READMEs and `THIRD-PARTY-NOTICES.md`.

Run focused tests while iterating. Before handing off implementation changes, run `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked` and `cargo deny --locked check`. For changes to matching code, also run `scripts/parity.py` against the reference and report its result.
